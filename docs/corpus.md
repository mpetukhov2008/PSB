# Формат базы знаний

Корпус — UTF-8 JSON. Минимальный пример:

~~~json
{
  "corpus_kind": "provided",
  "documents": [{
    "id": "approval-2026",
    "title": "Регламент согласования договоров",
    "family": "approval",
    "kind": "company",
    "revision": "Редакция с 01.07.2026",
    "effective_from": "2026-07-01",
    "effective_to": "",
    "sections": [{"locator": "п. 2.1", "text": "Точный текст предоставленного положения."}]
  }]
}
~~~

corpus_kind принимает demo для синтетических данных и provided для предоставленной базы. Переключайте его только после фактической замены текстов.

id — уникальная строка из латинских букв, цифр, _ и -. family объединяет редакции одного документа. kind — company или law. Поле revision содержит подпись редакции. effective_from включается в интервал, effective_to не включается; пустой конец означает отсутствие заданной даты окончания.

У документов компании обязательна дата начала редакции. Пересекающиеся интервалы одной family отклоняются. Нельзя смешивать law и company в одной family. Законы загружаются только в текущей редакции; архивные выводы не строятся по текущему тексту.

Разделы sections содержат locator и text. Указывайте реальные пункт, статью, страницу или абзац. Автоматический импорт не определяет юридическое значение изменений: периоды и связи проверяет автор корпуса.

## Импорт из файлов

Подготовьте папку с оригиналами и manifest.json:

~~~json
{
  "corpus_kind": "provided",
  "documents": [{
    "id": "reg-1",
    "title": "Предоставленный регламент",
    "family": "reg",
    "kind": "company",
    "revision": "Редакция 1",
    "effective_from": "2026-01-01",
    "effective_to": "",
    "file": "reglament.docx"
  }]
}
~~~

Из корня репозитория:

~~~bash
python scripts/import_corpus.py --manifest data/source/manifest.json --output data/knowledge.json
~~~

Пути file разрешаются только внутри каталога манифеста. Поддерживаются TXT, MD, DOCX. Для PDF:

~~~bash
python -m pip install -r requirements-import.txt
~~~

PDF извлекается постранично; пустая страница вызывает ошибку, чтобы не пропустить скан. OCR не выполняется. DOCX разбирается по абзацам, без выдуманных номеров страниц; сложные таблицы и колонтитулы требуют ручной проверки. TXT/MD делятся по пустым строкам.

После импорта обязательно сверьте положения, таблицы, суммы и даты с оригиналами. Составные редакции после допсоглашений готовятся явно: исходный и новый тексты одной family не должны действовать одновременно. Оригиналы не отправляются в интернет импортёром.

Для ручного корпуса можно заполнить sections напрямую без file. Не включайте реальные персональные данные или секреты. Файлы data/ игнорируются Git; право публикации материалов организаторов нужно проверить отдельно.
