# Передача ОПОРЫ · 1.2.0

Состояние: программный MVP с поддержкой предоставленной базы и формата платформы.
Работающий URL и ключ API не содержались в переданных материалах. Поэтому первый живой
модельный прогон и итоговая юридическая приёмка остаются обязательными.

## Что сделано

| Часть | Реализация |
|---|---|
| Данные | Импорт ZIP с TXT/MD/DOCX, 21 документ предоставленной базы успешно прочитан локально |
| Метаданные | Устойчивые ID, SHA-256 оригиналов, номера пунктов, интервалы редакций и дата выгрузки законов |
| Версии | Старый/новый регламент, дата из вопроса, включая месяц; уточнение при смене редакции внутри месяца |
| Договоры | Разные контрагенты и номера, последнее уточнение пользователя, отдельные допсоглашения |
| Поиск | BM25-подобный поиск, нормализация форм слов, ограниченный словарь синонимов |
| Дополнительный поиск | API embeddings и rerank по предоставленному контракту; fallback и трассировка |
| Ответ | Генерация, проверка существования ID и точности цитаты, независимый вызов той же модели |
| Устойчивость | Инструкции для ИИ в служебной записке не индексируются, оригинал остаётся доступен |
| Сдача | Официальный CSV id,question → id,answer; порядок, кавычки, независимые диалоги |
| Комплект | Быстрый запуск, Docker, ZIP по списку разрешённых файлов, инструкции и CI |

Корпус и эталонные ответы не включены в публичный репозиторий.
Воспроизводимое подключение данных описано в README. Решение не читает demo_output.csv.

## Первые действия команды

1. Положить knowledge-base.zip и demo_questions.csv в data, выполнить scripts/prepare_data.py.
2. Запустить START_PSB.cmd или python -m psb.launcher. Убедиться, что база предоставленная.
3. Внести LLM_BASE_URL и LLM_API_KEY в локальный .env; перезапустить сервис.
4. Прогнать solution.py на демонстрационных вопросах с --report artifacts/model.json.
5. Сверить каждый ответ с demo_output.csv и первоисточником, затем пройти независимые вопросы.
6. Собрать ZIP, загрузить на платформу, проверить ограничения и результат.

## Результаты, которые нельзя смешивать

Первичный локальный поиск: 18 вопросов, 17 с размеченными основаниями, один отрицательный.
В первых 12 результатах полный набор оснований был найден для 16 из 17 положительных
вопросов. Средняя доля найденных оснований по положительным вопросам — 0.9706.
Это предварительный замер до последующих исправлений. Локальное окружение отключилось
до повторного полного замера на этой базе. Для финальной версии результат следует пересчитать.

Прохождение CI подтверждает программные сценарии на синтетических независимых данных.
Ни CI, ни описанный поиск не подтверждают юридическую точность или оценку LLM-судьи.

## Ограничения и дальнейшее развитие

- Нормализация русского языка эвристическая. Embeddings работают по локальному пулу
  кандидатов, а не как полный векторный индекс всей базы.
- Импорт дат ориентирован на структуру переданного корпуса. Произвольные документы
  без явно определяемой даты требуют манифеста, а не выдуманной даты начала.
- Законы представлены снимком текущего текста. Исторические нормы и будущие редакции
  не восстанавливаются автоматически. Дата выгрузки не является юридической датой.
- Допсоглашение не переписывает исходный договор автоматически: обе части передаются
  модели с условием применимости. Ошибки смыслового выбора требуют живой проверки.
- Проверяющий использует ту же модель и может повторить её ошибку. Правила отсечения
  инструкций ловят лишь очевидные формы атак.
- Без модели пользователь видит выдержки с явным предупреждением, а не юридический вывод.
- История хранится только во вкладке; исходный PDF и OCR не нужны текущему TXT-корпусу.
- Сервис локальный. Для общего размещения нужны аутентификация, TLS, ограничения нагрузки
  и согласованный режим хранения документов.
- Время CSV-прогона зависит от числа API-вызовов, таймаутов и лимитов сервиса.

Не возвращать внешний поиск, не выдавать тестовые данные за предоставленные,
не включать ключи и эталоны в ZIP. Публикацию исходного корпуса согласует владелец.
