# Проверки ОПОРЫ

## Основной прогон

```bash
python -m unittest discover -s tests_psb -v
python -m compileall -q psb scripts solution.py
node --check psb/static/chat.js
python -m psb.launcher --check
```

CI запускает Python 3.10/3.12/3.14 на Linux, Windows с реальным CMD, браузер,
Docker, импорт PDF и сборку ZIP. Две Windows-проверки в Linux пропускаются намеренно.

## Покрываемые сценарии

- Редакции и границы действия, отсутствие истории закона, месяцы и конфликт дат.
- ZIP: полный текст, устойчивые ID, SHA-256, опасные пути, недопустимые форматы.
- Похожие контрагенты, последнее уточнение, номера договоров и связанные изменения.
- Явная инструкция для ИИ исключена из поиска; полезный текст записки сохраняется.
- Источник не существует, цитата выдумана, проверяющий отказал, отказ пустой.
- HTTP API модели: генерация и отдельная проверка, авторизация, запрет редиректа.
- API embeddings/rerank: формат, кэш, сбой и сохранение локального ранжирования.
- CSV: кавычки, порядок строковых ID, диалоги, повторы ID, независимость вопросов.
- Реальный запуск solution.py из другой папки; ZIP без ключей и пользовательских данных.
- .env как данные, отсутствие утечек в ошибках, свободный порт, быстрый запуск.
- Host/Origin, лимит тела, некорректный путь, мобильный экран, темы, источник и экспорт.

Независимые синтетические фикстуры в tests_psb/test_submission.py не копируют
эталонные ответы из demo_output.csv в исполняемое решение.

## Прогон предоставленных вопросов

```bash
python solution.py --questions data/demo_questions.csv --corpus data/knowledge-base.zip --offline --output artifacts/offline.csv --report artifacts/offline.json
```

Он проверяет чтение, поиск и формат. Модельные ответы так не оцениваются.
Для настоящего прогона заполните API и уберите --offline, затем вручную сопоставьте
каждый ID с demo_output.csv и оригинальным положением.

## Измерение поиска

```bash
python scripts/evaluate.py --corpus data/knowledge.json --questions data/demo_questions.csv --labels data/retrieval_labels.json --output artifacts/retrieval.json
```

Формат ручной разметки — объект по ID вопроса:

```json
{
  "001": {"evidence": [
    {"source_file": "точное имя файла.txt", "locator": "п. 2.1", "text_contains": "фрагмент основания"}
  ]},
  "002": {"evidence": [], "expected_status": "insufficient"}
}
```

Каждый вопрос требует явной разметки. Пустой evidence помечает отрицательный кейс.
Отчёт считает долю найденных оснований, полные вопросы и MRR среди положительных,
а также локальную задержку. Отказы и юридическая точность остаются null.

Первичный локальный замер: 18 вопросов, 17 положительных, 16 полных наборов оснований
в первых 12 результатах; средняя доля найденных оснований 0.9706. Замер предшествовал
последующим исправлениям морфологии. Его нельзя представлять как финальную
точность или скор платформы. Для новой версии требуется повторный замер.

## Приёмка модели

Обязательно проверить полный ответ, частичный ответ, отсутствие сведений, ложную
предпосылку, неоднозначный договор, исторический вопрос, условие допсоглашения,
противоречия, неправомерный запрос, смену роли и сбой API. Проверять не только наличие
цитаты, но и то, обосновывает ли она весь вывод. Все результаты фиксировать вместе
с fingerprint корпуса, моделью и SHA кода. Сейчас живой API не проверен.
