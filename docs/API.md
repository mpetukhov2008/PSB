# HTTP API и локальный JSONL

Базовый адрес при обычном запуске — `http://127.0.0.1:8080`. Быстрый запуск может выбрать другой порт. Пользовательских учётных записей и серверной истории в прототипе нет.

## Маршруты

| Метод и путь | Результат |
|---|---|
| `GET /api/health` | Состояние сервиса, версия, число документов/фрагментов, тип и SHA-256 отпечаток корпуса, наличие конфигурации модели |
| `GET /api/documents` | Метаданные документов и тип корпуса |
| `GET /api/documents/{id}` | Метаданные и весь импортированный текст по разделам |
| `POST /api/chat` | Ответ или найденные выдержки; JSON-запрос обязателен |

`model_ready=true` означает, что заданы URL и имя модели. Здоровье API и юридическое качество не подтверждаются этим полем. Сами ключи ни один маршрут не возвращает.

## Запрос чата

```json
{
  "question": "Какой срок согласования договора?",
  "event_date": "2026-03-01",
  "document_ids": [],
  "history": [
    {"role": "user", "content": "Рассматриваем учебный регламент согласования"}
  ]
}
```

| Поле | Ограничение |
|---|---|
| `question` | Обязательно, 2–6000 символов после обрезки краёв |
| `event_date` | Необязательная строка `ГГГГ-ММ-ДД`; дата должна существовать |
| `document_ids` | Необязательный массив до 20 существующих ID; пустой — весь корпус |
| `history` | До 12 реплик, роли только `user`/`assistant`; до 6000 символов в реплике и до 32000 суммарно |
| Тело запроса | До 100000 байт, `Content-Type: application/json` |

Если дата не задана, распознаются `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ` в вопросе. Короткий уточняющий вопрос может унаследовать явную дату из предыдущего пользовательского сообщения. Без даты применяется текущая дата сервера. Конфликт единственной даты в тексте с полем даты вызывает 422. Несколько дат в тексте без явного поля даты требуют уточнения.

История не доказывает юридические факты. Для поиска короткой реплики добавляются до двух предыдущих пользовательских вопросов; ответы ассистента не становятся фрагментами корпуса.

## Результат

Основные поля:

```json
{
  "status": "answered",
  "message": "",
  "claims": [{
    "text": "Один вывод, подтверждаемый переданным положением",
    "evidence": [{"fragment_id": "document-1-0", "quote": "Точная цитата из корпуса"}]
  }],
  "missing": [],
  "sources": [],
  "event_date": "2026-03-01",
  "explicit_date": true,
  "corpus_kind": "provided",
  "corpus_fingerprint": "SHA-256 канонического JSON",
  "mode": "model",
  "verified": true,
  "stages": [{"name": "Название этапа", "elapsed_ms": 123}]
}
```

Это описание схемы; сокращённый пример не является настоящим юридическим ответом. В реальном результате `sources` содержит все найденные фрагменты с `id`, `document_id`, `title`, `family`, `kind`, `revision`, интервалом действия, `locator`, `text`. ID в цитатах должны существовать среди этих фрагментов. `verified` устанавливается только при выполненной модельной проверке; для ранних отказов и выдержек поле может отсутствовать.

| Статус | Значение |
|---|---|
| `excerpts` | Модель отключена; показаны только результаты поиска |
| `answered`, `corrected` | Проверенный модельный ответ либо исправление ошибочной предпосылки; есть выводы с цитатами |
| `partial` | Подтверждённая часть и явно указанные пробелы |
| `insufficient` | Нет достаточных оснований; объяснение пробела |
| `clarification` | Требуется уточнение запроса |
| `out_of_scope` | Непрофильный вопрос; классифицируется моделью при наличии найденного контекста |
| `refused` | Отклонение запроса; часть смены роли отсеивается до вызова модели |
| `verification_failed` | Сбой API либо неподтверждённый вывод; непроверенные выводы скрыты |

Точная цитата и `verified=true` не гарантируют юридическую правильность. Причины ошибок провайдера и его сырые ответы клиенту не выдаются.

## Ошибки HTTP

Ответ: `{"detail":"Понятное пояснение"}`.

| Код | Когда возникает |
|---|---|
| 400 | Некорректная длина или способ передачи тела |
| 403 | Посторонний Host/Origin |
| 404 | Неизвестный маршрут или ID |
| 408 | Истекло время чтения запроса |
| 413 | Тело не укладывается в лимит |
| 415 | Неверный Content-Type |
| 422 | Неверная структура, дата, история или выбранный документ |
| 429 | Уже выполняются четыре обработчика чата |
| 500 | Непредвиденная ошибка обработки без выдачи внутренних деталей |

## `solution.py`

Запуск: `python solution.py`. Одна строка JSON на вход — одна строка JSON на выход. Допускается строка-вопрос, объект запроса чата либо объект `messages`, последняя реплика которого принадлежит пользователю:

```json
{"messages":[{"role":"user","content":"Какие документы нужны?"}]}
```

Состояние между строками не сохраняется. Ошибочная либо слишком длинная строка (более 100000 символов) возвращает `invalid_request`; следующий кейс обрабатывается независимо. Ошибка настройки при старте приводит к ненулевому коду завершения и сообщению в stderr; stdout остаётся каналом результатов.

**Это локальный контракт.** Формат платформы организаторов и способ доставки результата ещё не подтверждены. Нельзя загружать адаптер как готовый официальный сабмит без проверки по их минимальному примеру.


## Дополнение версии 1.2

Веб-контракт сохранён. В ответ добавлены date_precision (day/month) и retrieval_notes.
При месяце дата event_date обозначает начало месяца, а не выдуманный точный день события.
При смене применимой редакции внутри месяца возвращается clarification.

Корпус может загружаться из ZIP или JSON. В метаданных документов доступны aliases,
related_ids, source_file, source_sha256 и snapshot_date; в положениях — snapshot_date.

CLI платформы теперь CSV: python solution.py, вход DATA_DIR/questions.csv и kb.zip,
выход submission.csv с id,answer. Прежний JSONL включается явно: python solution.py --jsonl.
См. README и delivery.md.
