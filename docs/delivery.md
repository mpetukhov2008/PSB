# Финальная сдача и автоматический скоринг ПСБ

## Разъяснение организаторов

Основание: ответ «Трек ПСБ / Hack&Change 2026» от **15.11.2026, 16:54**,
переданный владельцем проекта в чате.

| Формат | Назначение | Материалы |
|---|---|---|
| Финальная экспертная сдача | Работоспособность, архитектура, интерфейс и критерии кейса | PDF со ссылкой на репозиторий; полное веб-приложение в Docker |
| Автоматический скоринг | Проверка ответов LLM-судьёй | Отдельный ZIP с solution.py |

В итоговом результате онлайн-этапа **70% составляет скор LLM-судьи и 30% —
экспертная оценка**. Окончательный скор LLM-судьи рассчитывается на **private-выборке**;
публичный лидерборд не является гарантией этого значения.

## Основной комплект для экспертов

- PDF-презентация со ссылкой на зафиксированную версию репозитория.
- Полный исходный код веб-приложения, Dockerfile, compose.yaml и .dockerignore.
- README с однокомандным запуском, адресом сайта и порядком подключения базы и API.
- .env.example без рабочих ключей; используемые сервисы, модели и переменные описаны в README.
- Результаты проверок и известные ограничения; без выдуманного private-скора.

Строгих названий переменных нет. Используем LLM_BASE_URL, LLM_API_KEY, LLM_MODEL;
PSB_LLM_* поддерживаются как аналоги с приоритетом. Дополнительные сервисы используют
EMB_MODEL, RERANKER_MODEL и при необходимости отдельные ключи.

## Приёмка экспертного решения

1. Взять чистую копию зафиксированного коммита и подготовить .env по шаблону.
2. Поместить предоставленный knowledge-base.zip в data. Исходные данные не запекать в образ.
3. Выполнить docker compose up --build -d --wait и открыть http://localhost:8080/.
4. Проверить баннер предоставленной базы и 21 документ. Учебный режим не подменяет её.
5. С настоящим API проверить ответ, цитату и открытие источника, уточнение и исторический вопрос.
6. Проверить отсутствие данных, ошибочную предпосылку, допсоглашение и сбой сервиса.
7. Проверить мобильный вид, светлую/тёмную тему и выгрузку результата.
8. Перезапустить контейнер, повторить сценарий, затем остановить docker compose down.
9. В PDF указать запуск, архитектуру, использованные модели, результаты и ограничения.

Рабочий API всё ещё нужен для проверки генерации. Зелёный CI подтверждает программные
сценарии, включая Docker с тестовым корпусом; он не является юридической приёмкой.

## Отдельный контракт автоматического ZIP

Основание — предоставленный sample_submission.zip, его README и примеры CSV.

- Вход: DATA_DIR/questions.csv с колонками id,question и DATA_DIR/kb.zip.
- Допустимые запасные имена архива: knowledge-base.zip, knowledge_base.zip.
- Запуск: python solution.py.
- Результат: submission.csv в текущей рабочей папке, колонки id,answer.
- Все поля в двойных кавычках, один физический ряд на вопрос; порядок ID сохранён.
- Данные и ключи поставляет платформа, не сабмит.

API: POST /chat/completions, POST /embeddings, POST /rerank под общим базовым URL.
Авторизация Bearer. Имена переменных и моделей перечислены в README.
Исполняемое решение использует стандартную библиотеку, httpx не требуется.

## Сборка ZIP для LLM-судьи

```bash
python scripts/package_submission.py
```

Полученный artifacts/PSB_submission.zip содержит solution.py, psb/ и requirements.txt
на верхнем уровне архива. Данные, .env, эталонные ответы, история и отчёты исключены
списком разрешённых файлов. ZIP также собирается в CI и публикуется как PSB-submission.

## Проверка перед загрузкой

1. Выполнить автоматические проверки из TESTING.md.
2. Прогнать демонстрационные вопросы с настоящим API и сохранить локальный отчёт.
3. Проверить цитаты, даты, похожие имена контрагентов, частичные ответы и отказы.
4. Протестировать извлечённый ZIP из новой папки с DATA_DIR и входами платформы.
5. Подтвердить ограничения времени, памяти, архива и разрешённые модели.
6. Загрузить на платформу, проверить наличие всех ID, лог и оценку.
7. Зафиксировать SHA, версию, инструкции и результаты.
8. Для экспертной части подготовить PDF и полный Docker-проект по перечню выше;
   доступ жюри hack-and-change-2026 — если репозиторий приватный.

Реальный адрес API, ключи, точные ресурсные лимиты и результат платформы в переданных
файлах отсутствуют. Совместимость с предоставленным стартером проверяется локальными
контрактными тестами; это не означает прохождение скрытого тестирования платформы.
